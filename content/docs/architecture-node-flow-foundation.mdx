# Node Flow Foundation

Node flows are project-scoped, repeatable workflow graphs. The backend foundation includes typed contracts, validation, SQLite persistence, agent-skill attachment records, dashboard HTTP routes, and deterministic runtime execution for a safe initial node set.

## Backend Surface

- Contracts live in `src/contracts/node-flow-types.ts`.
- Validation lives in `src/domain/node-flows/node-flow-validation.ts`.
- Persistence lives in `src/repositories/node-flow-repository.ts`.
- Service behavior lives in `src/services/node-flow-service.ts`.
- Runtime execution lives in `src/services/node-flow-runtime-service.ts`.
- Dashboard routes live in `src/server/node-flow-routes.ts`.

## Validation

Graphs are normalized before persistence. Validation checks unique node ids, valid edge endpoints, acyclic execution order, required widget metadata, and JSON-safe default values. Widget fields support `text`, `textarea`, `number`, `boolean`, `select`, `json`, `secretRef`, and `keyValue`.

## Runtime

`NodeFlowRuntimeService.runFlow(projectId, flowId, input, options)` reloads the current flow, revalidates the graph, creates a `node_flow_runs` row, and records the parent execution through `execution_invocations` with `type: "node_flow"`.

The supported executable nodes are `input`, `set_fields`, `template`, `provider_prompt`, `http_request`, and `output`. Provider prompt nodes reuse the existing provider execution path and create linked `execution_invocations` rows with `type: "node_flow_node"`. HTTP request nodes support method, URL, headers, query, body, timeout, and JSON response extraction with bounded timeouts and clear validation failures.

Run and node-run payloads are masked for secret-like keys before persistence or API responses. Failed nodes stop downstream descendants unless the node sets `data.continueOnError = true`.

## Persistence

The app database stores:

- `node_flows`
- `node_flow_versions`
- `node_flow_agent_skills`
- `node_flow_runs`
- `node_flow_node_runs`

Graphs, widget schemas, run inputs, run outputs, and trigger payloads are stored as JSON text. Flow and node-run rows store linked execution invocation ids when a parent flow invocation or externally observable node step is recorded. Flow and attachment mutations publish project structure refreshes for realtime dashboard clients.

## HTTP Routes

The dashboard exposes project-scoped CRUD, validation, run execution, agent attachment, and run-read endpoints under `/api/projects/:projectId/node-flows`, `/api/node-flows/:flowId`, and `/api/node-flow-runs/:runId`. `POST /api/node-flows/:flowId/run` returns the run record, output, node statuses, and linked invocation ids.
